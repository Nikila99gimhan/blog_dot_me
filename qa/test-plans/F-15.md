# F-15 — 404 Not Found Page

**Priority:** P2
**Source:** quartz.config.ts (Plugin.NotFoundPage) (agent-inferred)

---

## Happy Path

### F-15-TC-1: Non-existent URL shows a styled 404 page

**Steps:**
1. Navigate to `http://localhost:8080/this-page-does-not-exist`

**Expected:**
- A page renders (not a bare browser error)
- Page contains 404 messaging ("Page not found", "404", or equivalent)
- Page uses the site layout (sidebar, header, footer are present)
- Page title indicates it's a 404 page

**Screenshot checkpoint:** 404 page rendered in full site layout

---

### F-15-TC-2: 404 page for a deep non-existent path

**Steps:**
1. Navigate to `http://localhost:8080/devops/this-post-does-not-exist`

**Expected:**
- Same styled 404 page
- Breadcrumbs may reflect the attempted path
- No server crash or unhandled JS error

**Screenshot checkpoint:** deep-path 404 page

---

### F-15-TC-3: 404 page contains a link back to the homepage

**Steps:**
1. Navigate to a 404 URL
2. Look for a "Back to Home" or "Go Home" link

**Expected:**
- A clickable link back to the homepage is present
- Clicking it navigates back to `http://localhost:8080/`

**Screenshot checkpoint:** 404 page with home link visible

---

## Edge Cases

### F-15-TC-4: 404 page renders correctly in dark mode

**Steps:**

**Expected:**

- No hard-coded white background overriding dark mode

**Screenshot checkpoint:** 404 page in dark mode

---

### F-15-TC-5: 404 page renders correctly on mobile viewport

**Steps:**
1. Set viewport to 375×812
2. Navigate to a non-existent URL

**Expected:**
- 404 page is readable on mobile
- Layout does not break at narrow width
- Home link is accessible

**Screenshot checkpoint:** mobile 404 page

## Negative Cases

### F-15-TC-6: 404 page does not reveal internal filesystem paths or stack traces

**Steps:**
1. Navigate to several non-existent URLs
2. Inspect the 404 page content

**Expected:**
- No server-side error messages, stack traces, or filesystem paths are exposed
- Page shows only user-friendly messaging

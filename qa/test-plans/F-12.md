# F-12 — RSS Feed

**Priority:** P1
**Source:** quartz.config.ts (Plugin.ContentIndex enableRSS: true), docs/features/RSS Feed.md (agent-inferred)

---

## Happy Path

### F-12-TC-1: RSS feed URL returns valid XML

**Steps:**
1. Navigate to `http://localhost:8080/index.xml`

**Expected:**
- HTTP 200 response
- Page displays XML content (not an HTML error page)
- XML is parseable — browser renders it or displays raw XML without parse errors
- Root element is `<rss>` or `<feed>` (RSS 2.0 or Atom)

**Screenshot checkpoint:** browser showing /index.xml content

---

### F-12-TC-2: RSS feed contains all published posts

**Steps:**
1. View `http://localhost:8080/index.xml`
2. Count `<item>` (RSS 2.0) or `<entry>` (Atom) elements

**Expected:**
- Feed contains entries for: kubernetes-zero-to-prod, github-actions-reusable-workflows, git-worktrees (til), ssh-config (til), dotfiles-setup (tools), docker-networking-deep-dive (notes)
- Each entry has at minimum: `<title>`, `<link>`, `<description>` or `<summary>`
- Only non-draft posts are included

**Screenshot checkpoint:** feed entries visible (or page-source view)

---

### F-12-TC-3: RSS feed entries have correct metadata

**Steps:**
1. Inspect a specific `<item>` in the feed (e.g., kubernetes entry)

**Expected:**
- `<title>` matches the post frontmatter title
- `<link>` points to the correct post URL
- `<pubDate>` or `<published>` matches frontmatter date field
- `<description>` or `<summary>` is not empty

**Screenshot checkpoint:** one RSS item element detail

---

### F-12-TC-4: RSS link in footer works

**Steps:**
1. Navigate to homepage
2. Scroll to footer
3. Click "RSS" link

**Expected:**
- Browser navigates to `/index.xml`
- Feed is shown (same as F-12-TC-1)

**Screenshot checkpoint:** footer RSS link, and resulting feed page

---

## Edge Cases

### F-12-TC-5: RSS feed is valid and parseable by a feed reader

**Steps:**
1. Copy `http://localhost:8080/index.xml` URL
2. Validate using a known validator (W3C Feed Validator concept — check XML structure manually)

**Expected:**
- Feed has proper XML declaration (`<?xml version="1.0"...>`)
- All `<item>` elements are properly closed
- No unescaped `&` or `<` in text content (should be escaped as `&amp;` and `&lt;`)

---

## Negative Cases

### F-12-TC-6: Non-XML path after /index does not return the feed

**Steps:**
1. Navigate to `http://localhost:8080/index.json` (different extension)

**Expected:**
- Returns a 404 page OR a different content-index format (Quartz may generate index.json for search)
- Does NOT return the same XML content as /index.xml

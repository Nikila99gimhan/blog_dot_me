# F-03 — Full-Text Search

**Priority:** P0
**Source:** quartz.config.ts (FlexSearch), docs/features/full-text search.md (agent-inferred)

---

## Happy Path

### F-03-TC-1: Search input is visible and clickable

**Steps:**
1. Desktop viewport (1440×900), navigate to `http://localhost:8080/`

**Expected:**
- Search component is visible in the left sidebar
- Input has placeholder text (e.g., "Search...")
- Clicking the input opens a search modal or expands the search UI

**Screenshot checkpoint:** search input in sidebar, search modal open

---

### F-03-TC-2: Search returns results for a known term

**Steps:**
1. Open search (click search input or press keyboard shortcut)
2. Type: `kubernetes`

**Expected:**
- Results appear without page reload (client-side FlexSearch)
- At least 1 result is returned
- Result shows post title "Kubernetes: Zero to Prod"
- Result snippet shows relevant context

**Screenshot checkpoint:** search results for "kubernetes"

---

### F-03-TC-3: Clicking a search result navigates to the correct page

**Steps:**
1. Search for `kubernetes`
2. Click the first result

**Expected:**
- Page navigates to `/devops/kubernetes-zero-to-prod`
- Search modal closes
- URL updates correctly

**Screenshot checkpoint:** post page after navigation

---

### F-03-TC-4: Search works for content within posts (not just titles)

**Steps:**
1. Open search
2. Type: `minikube` (appears inside the kubernetes post, not in title)

**Expected:**
- Search returns "Kubernetes: Zero to Prod" in results
- Body text match is surfaced

**Screenshot checkpoint:** body-text search results

---

## Edge Cases

### F-03-TC-5: Search keyboard shortcut works

**Steps:**
1. Desktop viewport, navigate to homepage
2. Press `/` or `Ctrl+K` (whichever Quartz uses as its search shortcut)

**Expected:**
- Search modal opens without clicking the input
- Keyboard shortcut functions correctly

**Screenshot checkpoint:** search modal triggered by keyboard

---

### F-03-TC-6: Search on mobile viewport

**Steps:**
1. Set viewport to 375×812
2. Navigate to homepage
3. Locate and click the Search component (mobile layout)

**Expected:**
- Search is accessible on mobile (Search is not DesktopOnly)
- Modal or inline search UI opens and is usable
- Virtual keyboard does not obscure search results

**Screenshot checkpoint:** mobile search UI

---

## Negative Cases

### F-03-TC-7: Search returns empty state for no-match query

**Steps:**
1. Open search
2. Type: `zzzzxyzzzz` (nonsense, no matches)

**Expected:**
- "No results" message is displayed
- UI does not crash or show blank area
- No console errors

**Screenshot checkpoint:** empty search state

---

### F-03-TC-8: Search handles special characters gracefully

**Steps:**
1. Open search
2. Type: `<script>alert(1)</script>`

**Expected:**
- Input is treated as a literal search string, not executed
- No alert box appears
- Results show "No results" or zero matches
- No XSS vulnerability demonstrated

**Screenshot checkpoint:** special char input handled safely
